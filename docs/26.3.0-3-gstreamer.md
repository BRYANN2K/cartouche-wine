# Cartouche Wine 26.3.0-3: winegstreamer

Release 26.3.0-3 (`BUILD_REVISION=3`) builds Wine `--with-gstreamer`. That lets
games play their videos through Media Foundation, DirectShow and the WM ASF reader
(H.264/AAC MP4, WMV/WMA, MPEG). Builds 26.3.0-1 and -2 were configured
`--without-gstreamer`, so `winegstreamer` was missing. The research behind this
is in `Cartouch-work/docs/research/26.3.0-3-wine-gstreamer.md`.

## Where GStreamer comes from

**Decision: we build the GStreamer tree that ships inside CodeWeavers' CrossOver
26.3.0 source tarball. We do not use the official GStreamer.framework pkg or
Homebrew.**

What the tarball contains (`crossover-sources-26.3.0.tar.gz`, SHA-256
`ac99c8ca…6872`, already pinned as `CX_SOURCE_SHA256`):
- `sources/gstreamer` is the GStreamer **1.24.4** monorepo. Its `meson.build`
  says `version : '1.24.4'`. It includes `subprojects/gstreamer`,
  `gst-plugins-base`, `-good`, `-bad`, `-ugly` and `gst-libav`, about 198 MB.
- `sources/glib` (2.78.0) is also there, but we do not build it.
- The tree has no FFmpeg. `subprojects/FFmpeg.wrap` is a git wrap that points
  at the `meson-6.1` branch of GStreamer's FFmpeg port.

Why we chose this over the official framework pkg:
- **One source offer.** GStreamer's corresponding source is the CodeWeavers
  tarball we already attach to every release. A binary framework would need us
  to find and attach the matching source for each of the framework's ~100
  bundled libraries, plus cerbero's patches.
- **LGPL by construction.** Every module is configured with
  `--auto-features=disabled` and `-Dgpl=disabled`. Only the plugins listed in
  `packaging/wine-crossover/gstreamer-plugins.txt` are enabled. FFmpeg is
  configured with neither `--enable-gpl`, `--enable-version3` nor
  `--enable-nonfree`, and `build-gstreamer.sh` checks for that in `config.h`.
  The plugin license check (below) fails on anything that is not LGPL.
- **Reproducible in CI.** The inputs are the pinned CX tarball, one pinned FFmpeg
  tarball, and Homebrew's glib, meson, ninja and nasm. `--wrap-mode=nofallback`
  means meson never downloads anything.
- **Matches what CrossOver is built from.** It is the same GStreamer version
  CodeWeavers ships the source for.
- **Costs:** about 10–20 more CI minutes, which is unmeasured on the Mac. We
  also maintain a plugin list ourselves.

Option (b), the official LGPL framework, stays the fallback if the source build
cannot be made to work on the runner. It would need its pkg URL and SHA-256
pinned after downloading it. Nothing for it is pinned now.

## Run time: what the Cartouche app must do

**Nothing is required.** libgstreamer finds its plugin folder with `dladdr`
relative to its own file (`priv_gst_get_relocated_libgstreamer` in
`gst/gstregistry.c`, used whenever `GST_PLUGIN_SYSTEM_PATH[_1_0]` is unset).
Since `<root>/lib/libgstreamer-1.0.0.dylib` sits next to
`<root>/lib/gstreamer-1.0`, winegstreamer uses the bundled plugins with no
environment variable. `check-gstreamer.sh` tests exactly this path under
`env -i`.

**Recommended hardening for `dylib/feats/compat_run.sh`.** This is optional,
next to the existing `WINEDLLPATH` export:
```sh
export GST_PLUGIN_SYSTEM_PATH_1_0="$CX_ROOT/lib/gstreamer-1.0"
export GST_PLUGIN_PATH_1_0=""          # ignore a user's GST_PLUGIN_PATH
export GST_REGISTRY_1_0="$HOME/Library/Caches/Cartouche/gstreamer-1.0/registry-<runner id>.x86_64.bin"
```
Without `GST_REGISTRY_1_0`, the plugin cache is GLib's user cache file
(`registry.x86_64.bin`), which a Homebrew GStreamer on an Intel Mac also uses.
Both stay functional, because each process drops and rescans plugins outside its
own paths, but each rescans whenever the other has run. A per-runner registry
avoids that. Also without the variables, `~/.local/share/gstreamer-1.0/plugins`
is scanned too.

We did not use a `bin/wine` wrapper script. The manifest's `loader` is
`bin/wine`, the app uses it as `WINELOADER`, and the ntdll patcher expects the
real binary layout, so a wrapper was the riskier choice.

## Verified here (Linux x86_64, not the Mac)

- `build-gstreamer.sh` ran end to end on Linux with meson 1.12.1 against system
  GLib 2.80. All 21 listed plugins were built, and the option names are right
  for every module.
- `check-gstreamer.sh` passed on a package-like tree built from that output, with
  `GST_PLUGIN_EXT=so` and an LD_LIBRARY_PATH wrapper for gst-inspect. No `GST_*`
  variable was set, so the dladdr relocation found `lib/gstreamer-1.0` by itself.
  It reported 0 blacklisted plugins, every element present, and every license
  LGPL except mpegpsdemux.
- `filesrc ! decodebin ! videoconvert ! fakesink` reached EOS on an H.264+AAC
  MP4, a WMV2+WMA2 ASF and an MPEG-2 PS file.
- Size on Linux: the plugins plus the GStreamer and FFmpeg libraries they load
  are about 18 MB uncompressed, and about 3.7 MB xz-compressed for plugins plus
  all FFmpeg libs. Homebrew glib/gettext/pcre2 add a few MB on the Mac.
- Ran `python3 -m unittest discover -s packaging/tests -p 'test_wine_crossover.py'`,
  `sh -n` on all scripts, a YAML parse of the workflow, and `build.sh --dry-run`.

## What CI / a Mac must verify (unverified so far)

1. The meson builds on macOS 15 x86_64 with Homebrew glib. Check:
   - plugins come out as `libgst*.dylib` (`build-gstreamer.sh` fails if not)
   - FFmpeg's `--arch=x86_64 --cc=clang` builds with Homebrew nasm
2. bundle-deps:
   - pulls in exactly the GStreamer libs the plugins need, plus glib, gobject,
     gmodule, intl and pcre2
   - after it, `check-deps.sh` passes: no `/usr/local`, no absolute
     `LC_RPATH`, no absolute ids
   - `check_dlopen.py` finds no unbundled dylib name in the GStreamer, GLib or
     FFmpeg strings. If GLib names an optional library, add it to
     `dlopen-allow.txt` with a reason.
3. Wine's configure accepts our `GSTREAMER_CFLAGS`/`GSTREAMER_LIBS` and builds
   `winegstreamer.so`, and `otool -L` on it shows only `@rpath/libgst*`,
   `@rpath/libglib*` and `@rpath/libgobject*`.
4. `check-gstreamer.sh` passes in `build.sh` and in `verify.sh` on the runner,
   which proves the dladdr relocation through `@rpath` on macOS.
5. Gatekeeper and Rosetta on an Apple Silicon user Mac: winegstreamer `dlopen`s
   ad-hoc signed plugins from the downloaded archive. The Cartouche app already
   handles quarantine for the whole runner folder.
6. End to end: a game or test program that plays a cutscene via Media Foundation
   (`MFCreateSourceReaderFromURL` + `ReadSample`) and DirectShow, run with
   `WINEDEBUG=+mfplat,+quartz`, and no `winegstreamer: failed to create`
   messages. There is no automated MF probe in CI yet; the research proposes one.
7. Build time: the job's timeout stays at 300 minutes.

## Open questions

- **Patents.** H.264, AAC, WMV/VC-1 and WMA decoders are in, the same exposure
  every FOSS Wine-on-macOS build accepts. HEVC and E-AC-3 are left out on
  purpose; MPEG-2, MP3 and AC-3 patents have expired. openh264, x264 and x265
  are not built. None of this is legal advice, and it has had no legal review.
- **Plugin coverage.** These are not built, and games using them will fail:
  - Ogg/Vorbis/Theora as containers: the `ogg`/`vorbis`/`theora` plugins need
    libogg etc. `avdec_vorbis`/`avdec_theora` exist, but there is no Ogg demuxer.
  - `mpg123`: MP3 is decoded by `avdec_mp3` instead.
  - Bink/Smacker: games use their own DLLs.
  - AV1, HEVC.
  - Hardware decoding: no VideoToolbox (`--disable-autodetect`).

  Adding a plugin means adding one line to `gstreamer-plugins.txt` (plus its
  external library, if any).
- **orc is disabled.** videoconvert and audioconvert use their C paths. Building
  with Homebrew `orc` (BSD-2) could speed up large-video conversion under Rosetta.
  The effect of its JIT under Rosetta is untested.
- **Size on the Mac** is unmeasured; the estimate is +6–8 MB to the xz archive.
- **Registry location.** Which folder GLib's `g_get_user_cache_dir()` returns on
  macOS for this GLib version is unverified. The app setting
  `GST_REGISTRY_1_0` removes the question.
- **Homebrew Intel Tier 3.** If x86_64 glib bottles stop being published,
  `brew install glib` builds from source. The alternative is building
  `sources/glib` from the CX tarball, which needs proxy-libintl and pcre2
  handled without wraps.
- **gst-inspect-1.0 ships** in `libexec/gstreamer-1.0`, about 100 KB. It is there
  for the checks and for support diagnostics. It is not on `PATH` for users.
